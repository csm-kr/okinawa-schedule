# User Flow

> **Refs**: [USER_JOURNEY](./USER_JOURNEY.md) · [SCREEN_FLOW](../design/SCREEN_FLOW.md) · [SCREENS](../design/SCREENS.md)

목표 완료까지의 단계와 분기를 클릭 단위로 기술한다. 화면 전환 맵은
[SCREEN_FLOW](../design/SCREEN_FLOW.md)와 짝을 이룬다.

## 플로우 1: 가족이 "지금 일정" 확인 (보기 전용, 핵심 경로)

```
링크 클릭(카톡) 또는 홈화면 아이콘
   │
   ▼
공개 타임라인 `/`
   │
   ├─ (자동) 현재 상태 카드에 "지금 진행 중 / 다음" 표시
   ├─ 날짜 탭 전환 ──▶ 해당 날짜 타임라인 + 동선 지도 갱신
   ├─ 항목 🔗 탭 ──▶ (새 탭) 외부 지도 열기
   └─ 상태 카드 탭 ──▶ 현재 항목으로 스크롤
```

### 단계
1. `/`에 진입 → 서버가 일정을 읽어 렌더, 오늘 날짜 탭이 기본 선택.
2. 현재 상태 카드가 스크롤 없이 "지금 진행 중"(또는 "다음", "행사 시작 전/종료")을 표시.
3. 날짜 탭으로 다른 날 일정 확인 → 목표 완료(원하는 일정 확인).
4. (선택) 타임라인 아래 동선 지도로 그날의 경로를 보고, 음식·숙소 🔗로 위치를 새 탭에서 연다.

### 분기·예외
| 지점 | 조건 | 분기 결과 |
|---|---|---|
| 진입 | 행사 기간 밖(전/후) | 상태 카드가 "행사 시작 전" / "모든 일정이 끝났어요" |
| 진입 | 등록 일정 0건 | "아직 등록된 일정이 없어요" 빈 상태 |
| 진입 | 데이터 로드 실패 | "일정을 불러오지 못했어요" + [다시 시도] (가능 시 캐시 표시) |

## 플로우 2: 편집자가 일정 수정 (보호된 경로)

```
`/admin` 진입
   │
   ├─ 비밀번호 입력 ─▶ (틀림) 흔들림 + 에러 → 재입력
   │                  └▶ (맞음) 쿠키 발급 → 편집 화면
   ▼
편집 화면
   ├─ 날짜 탭 선택 → 항목 추가/수정/삭제
   └─ [저장] ─▶ (version 일치) 저장 + revalidate → 공개 반영
              └▶ (version 불일치) 409 "다른 곳에서 바뀌었어요" → 새로고침 후 재저장
```

### 단계
1. `/admin`에서 공용 비밀번호 입력 → 서버 검증 → httpOnly 쿠키.
2. 날짜 탭 선택 → 항목 시각/제목/장소/메모 편집, [+ 일정 추가], 항목 [삭제].
3. [저장] → `PUT /api/itinerary`(expectedVersion 포함) → 성공 토스트, 공개 `/` 갱신.

### 분기·예외
| 지점 | 조건 | 분기 결과 |
|---|---|---|
| 로그인 | 비밀번호 틀림 | 입력칸 흔들림 + "비밀번호가 달라요" |
| 저장 | version 불일치 | 409 거부 + "새로고침 후 다시 저장" |
| 저장 | 네트워크 실패 | 에러 토스트 + 재시도 |
