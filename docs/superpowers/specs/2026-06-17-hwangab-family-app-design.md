## Problem Statement

조인수·김인숙 여사님 환갑잔치 겸 가족 여행(2박 3일 이상)에서, 가족들이 "지금 몇 시에
어디서 뭘 하는지"를 카톡에 흩어진 메시지를 뒤지지 않고 **링크 하나로 즉시** 확인할 수
있게 한다. 회원가입 없이, 안드로이드·iOS 어디서나 동일하게, 모바일에서 본다.

## What Makes This Cool

핵심 마법은 **라이브 타임라인**이다. 사용자가 앱을 열면 현재 시각(Asia/Seoul) 기준으로
"지금 진행 중" 일정이 자동으로 강조되고, "다음 일정"이 바로 아래에 보인다. 종이/PDF
일정표와 달리, 매 순간 "지금 내가 어디 있어야 하는지"를 스스로 짚어준다. 군더더기
(카운트다운·사진·축하글·지도)는 의도적으로 넣지 않아 깔끔함을 유지한다.

## Constraints

- 모바일 우선 (가족 대부분 폰으로 봄). 안드로이드·iOS 동일 동작.
- 회원가입·계정 없음. 가족만 보는 비공개성은 "링크를 아는 사람만" 수준(by obscurity).
- 일정을 **재배포 없이 런타임에** 직접 수정할 수 있어야 한다 (공용 비밀번호 /admin).
- 무료로 운영 (Vercel + KV 무료 티어).
- PWA: 홈화면 추가 시 앱 아이콘처럼 보이고 열린다.

## Premises (Phase 3 — 사용자 전원 동의)

1. 카톡에 흩어지는 일정 대신 "항상 최신인 링크 1개 + 홈화면 아이콘"이 낫다 → 웹앱 형태가 맞다.
2. 일정을 직접 고치려면 런타임 편집이 필요하고, 공용 비밀번호로 들어가는 앱 내 /admin 폼이 그 수단으로 적절하다.
3. 핵심 가치 = "현재 시각에 따라 지금/다음 일정을 자동으로 짚는 라이브 타임라인" (정적 PDF 일정표 대비).
4. 웹앱이라 배포 = 공개 URL이 필요하다 → 무료 호스팅(Vercel 등)에 올려야 하고, 계정·배포는 사용자 개입이 필요할 수 있다.

## Approaches Considered (Phase 4)

### Approach A: Next.js + 가벼운 KV 저장소 (Vercel 배포) — 채택
Next.js 앱 하나. 일정은 JSON 한 덩어리로 KV(Upstash/Vercel KV 무료)에 저장. `/admin`은
공용 비밀번호(env)로 보호. 공개 페이지는 클라이언트에서 현재 시각으로 "지금" 강조.
PWA(manifest + service worker), Vercel 무료 배포.
- Effort: M · Risk: Low
- Pros: 하네스 템플릿(Next.js)과 일치 · 앱 1개·배포 1번 · 무료 · 폰에서 바로 편집 · PWA 쉬움
- Cons: 외부 KV 서비스 + 비밀 2종(KV 토큰·admin 비번) 필요

### Approach B: Next.js + Prisma + Postgres (정석 관계형 DB)
A와 같되 관계형 DB(Supabase/Neon 무료)에 일정 행(row)으로 저장.
- Effort: L · Risk: Med
- Pros: 확장 여지 · 템플릿 Prisma 전제와 일치
- Cons: 일정 한 덩어리에 관계형 DB는 과설계 · DB 프로비저닝·마이그레이션·서버리스 커넥션 부담

### Approach C: 정적 SPA(Vite+React) + Cloudflare Pages Functions/KV
정적 프런트 + 편집용 작은 엣지 함수/KV.
- Effort: M · Risk: Med
- Pros: 런타임 가장 가벼움·빠름
- Cons: 하네스 Next.js 템플릿과 불일치 · 편집 글루를 직접 만들어야 함

## Recommended Approach: A

"직접 수정 + 무료 + PWA"를 모두 만족하면서 하네스 Next.js 스택을 그대로 타고, B의 관계형
DB 과설계를 피한다. 일정은 작은 단일 문서이므로 KV에 JSON 한 덩어리로 충분하다.

## UX & 화면 설계

### 대상과 디자인 원칙
시청자는 **다세대 가족**이다. 환갑잔치이므로 60대 이상 어르신(주인공 본인·친척)이 폰으로
보는 비중이 크다. 이게 모든 UX 결정의 축이다.

1. **큰 글씨·높은 대비 우선** — 본문 17–19px, 시간/제목은 더 크게. 명도 대비 WCAG AA 이상.
   "작고 예쁜" 것보다 "멀리서도 읽힌다"를 택한다.
2. **한 손·세로 스크롤** — 가로 제스처 최소화. 주요 동작(날짜 전환)은 화면 위쪽 큰 탭으로.
3. **"지금 뭐?"에 1초 안에 답** — 앱을 열면 스크롤 없이 현재 상태가 먼저 보인다.
4. **절제** — 카드 남발·장식 금지. 정보(시간·제목·장소)가 주인공. 색은 "지금"을 가리키는
   데만 쓴다.
5. **읽기 모드가 기본, 편집은 숨김** — 가족은 보기만. 편집(/admin)은 링크에 노출 안 함.

### 화면 1 — 공개 타임라인 `/` (가족이 보는 화면)

```
┌─────────────────────────────┐
│  조인수 · 김인숙 여사님       │   ← 헤더(작고 단정). 한 줄 제목 +
│  환갑잔치 · 9.19–21          │     날짜범위 subtitle
├─────────────────────────────┤
│ ┌─────────────────────────┐ │
│ │ ● 지금 진행 중            │ │   ← 현재 상태 카드(최상단, 포인트색)
│ │ 가족 만찬                 │ │     · 행사 중: "지금 진행 중: ○○"
│ │ 18:00–20:00 · 한정식 본관 │ │     · 일정 사이: "다음: ○○ 20:30"
│ │ 다음 ▸ 케이크 커팅 20:30  │ │     · 기간 전/후: "행사 시작 전 /
│ └─────────────────────────┘ │       모든 일정이 끝났어요"
├─────────────────────────────┤
│ [1일차 9/19] [2일차·오늘] [3일차]│ ← 날짜 탭(세그먼트). 기본 선택=오늘
├─────────────────────────────┤     (기간 밖이면 1일차). 오늘 탭 표시
│  09:00 ─○  도착·체크인        │   ← 지난 일정: 흐리게(낮은 명도)
│  12:00 ─○  점심 (호텔 뷔페)   │
│  ▌18:00 ●  가족 만찬   [지금] │   ← 현재: 좌측 컬러바+굵게+큰 글씨
│  │        한정식 본관          │     +"지금" 뱃지, 자동 스크롤로 노출
│  20:30 ─○  케이크 커팅        │   ← 예정: 선명한 기본 스타일
│  21:30 ─○  자유 시간          │
│              ⋮                │
└─────────────────────────────┘
```

**구성 요소**
- **헤더**: 행사명 + 날짜범위. 스크롤 시 축소 고정(sticky) 또는 단순 상단 고정.
- **현재 상태 카드**: 화면 최상단. `getItemStatus`로 계산한 현재 진행 item을 강조 표시하고
  "다음 ▸"으로 바로 다음 item을 한 줄 미리보기. 탭하면 해당 항목으로 스크롤.
- **날짜 탭**: 세그먼트 컨트롤. 2박3일이면 3개. 오늘에 해당하는 탭을 기본 선택 + 점/언더라인
  표시. 탭은 큰 터치 영역(최소 44px 높이).
- **타임라인 리스트**: 세로 축. 각 item = `시각 · 점(dot) · 제목 · 장소 · 메모`. 좌측 시간축의
  점 색이 상태를 반영.

**item 상태 3종 (시각 규칙)**
| 상태 | 의미 | 스타일 |
|------|------|--------|
| past | 이미 지난 일정 | 텍스트 명도↓(예: 회색), 점 비움(○), 글씨 기본 |
| current | 지금 진행 중 | 좌측 포인트색 바(▌), 굵게, 글씨 1단계 크게, `지금` 뱃지, 채운 점(●) |
| upcoming | 앞으로 | 선명한 기본 색, 점 테두리(◌) |

### 인터랙션 & 상태

- **자동 "지금" 갱신**: 시간이 흐르면 강조가 바뀌어야 한다. 클라이언트에서 **30–60초마다
  현재 시각(KST)을 재계산**해 상태 카드와 강조를 갱신(데이터 refetch 아님 — 가벼운 재렌더).
  데이터 자체는 페이지 포커스 시 또는 수 분 간격으로만 다시 읽는다.
- **타임존 고정**: 사용자 기기 시간대와 무관하게 항상 Asia/Seoul로 계산. (해외 가족 대비)
- **로딩**: 첫 진입 시 타임라인 스켈레톤(시간·줄 형태) 표시.
- **빈 상태**: 등록 일정 0건 → "아직 등록된 일정이 없어요" 한 줄(공개 화면엔 admin 안내 X).
- **에러**: 데이터 로드 실패 → "일정을 불러오지 못했어요" + [다시 시도] 버튼. 가능하면
  직전에 본 데이터를 캐시로 보여줌(PWA 캐시).
- **스크롤 위치**: 진입 시 current item이 화면에 보이도록 자동 스크롤(부드럽게).

### 화면 2 — 관리자 `/admin` (가족 중 편집자만)

```
[로그인]                         [편집]
┌───────────────────┐          ┌─────────────────────────────┐
│  가족 비밀번호       │          │ 일정 편집      [로그아웃]     │
│ ┌───────────────┐ │          │ [1일차] [2일차] [3일차]       │
│ │ ••••••        │ │          │ ┌─────────────────────────┐ │
│ └───────────────┘ │          │ │ ⌚ 18:00  제목[가족 만찬]  │ │
│   [ 들어가기 ]     │          │ │ ⌚ 20:00  장소[한정식 본관]│ │
│  비번 틀림시 흔들림  │          │ │ 메모[      ]        [삭제]│ │
└───────────────────┘          │ └─────────────────────────┘ │
                               │      [+ 일정 추가]           │
                               │   ───────────────────────    │
                               │      [ 저장 ]  (성공 토스트)  │
                               └─────────────────────────────┘
```

- **로그인**: 비밀번호 1개 입력 → 서버 검증 → httpOnly 쿠키. 틀리면 입력칸 흔들림 + "비밀번호가
  달라요". 계정/아이디 없음.
- **편집**: 날짜 탭으로 day 선택 → item 목록. 각 item 인라인 편집(시각=네이티브 `<input
  type="time">`, 제목·장소·메모=큰 텍스트필드). [+ 일정 추가]로 빈 item 생성. 항목별 [삭제].
  **정렬은 시작 시각 기준 자동**(드래그 정렬은 비목표).
- **저장**: 화면 전체를 한 번에 `PUT /api/itinerary`로 저장(낙관적 X, 명시적 저장 버튼). 성공
  토스트, 실패 시 에러. 모바일에서 큰 저장 버튼 하단 고정.

### 비주얼 디렉션 (DESIGN_GUIDE — D6 확정: 다정한 파스텔 + 큰 글씨)

**팔레트 (확정)**
| 토큰 | 값 | 용도 |
|------|----|----|
| `bg/cream` | #FFF9F3 | 화면 베이스 |
| `ink` | #3D3430 (따뜻한 브라운) | 본문·제목 텍스트 |
| `ink/muted` | #8A7F76 | past 일정·보조 텍스트 |
| `accent/coral` | #E07A5F (살구) | "지금" 강조 바·점·뱃지, 포인트 |
| `accent/coral-strong` | #C75B43 | 살구가 텍스트/버튼 라벨이 될 때(대비 보강용) |
| `surface` | #FFFFFF | 상태 카드·입력 필드 표면 |
| `line` | #EFE4DA | 경계선·구분 |

> **접근성 주의(중요)**: 살구 `#E07A5F`는 크림 위에서 대비가 약하다(≈2.5:1). 그래서
> **살구는 면(배경 바·점·뱃지 배경)에만** 쓰고, 그 위 글자는 흰색 또는 `ink`로 둔다. 살구가
> **글자색/버튼 라벨**이 되어야 하면 `accent/coral-strong #C75B43`(크림 위 ≈4.5:1, AA 통과)로
> 대체한다. 본문은 항상 `ink`(고대비)로. 어르신 가독성이 최우선.

- **타이포**: 한글 고딕 가독성 우선(Pretendard 또는 시스템 한글 스택). **rem 기반**(고정 px 지양)
  으로 기기 글씨 확대에 대응. line-height 1.5–1.6.

**타입 스케일 (어르신 가독성 — 큰 글씨가 기본)**
| 용도 | 크기 | 두께 | 비고 |
|------|------|------|------|
| 현재 상태 카드 제목("지금 진행 중") | 26px | 700 | 진입 후 가장 먼저 읽히는 글자 |
| 화면 헤더(행사명) | 24px | 700 | |
| 시간 숫자(예 18:00) | 22px | 700 | **tabular-nums**, 스캔 쉽게 |
| 일정 제목(item title) | 21px | 600 | |
| 본문/장소 | 18px | 400–500 | **하한 18px** |
| 보조/메모 | 16px | 400 | **14px 미만 절대 금지** |

**버튼·터치 규격 (확실히 누를 수 있게)**
- 주요 버튼(들어가기·저장): 높이 **56px**, 글자 18–20px/600, 좌우 패딩 ≥20px, 화면 폭에 가깝게 크게,
  하단 고정. 채움 = `accent/coral-strong`(#C75B43) 배경 + 흰 글자(대비 AA).
- 보조/일반 버튼: 높이 **≥48px**, 글자 ≥17px. `ink` 테두리 + 크림 배경.
- 날짜 탭: 높이 ≥48px, 글자 18px+, 선택 탭은 밑줄+굵게+색으로 **뚜렷이**.
- 위험 버튼(삭제): 색·위치로 분리(주요 액션과 멀리). 실수 방지.
- 터치 간격: 인접 터치 타깃 사이 ≥12px. 포커스 링 뚜렷(키보드/스위치 접근).
- 활성/비활성/누름 상태가 색·명암으로 분명히 구분.

- **모서리/카드**: 부드러운 라운드(상태 카드·입력은 12–16px). 단, 모든 요소를 균일 `rounded-2xl`로
  도배하는 슬롭은 회피. 구분은 `line`·여백 위주.
- **색 사용 규칙**: 크림 베이스 + **포인트색 1개(살구)**. 포인트는 오직 "지금" 강조와 주요 버튼에만.
- **모션**: 최소. 상태 카드 등장·탭 전환에 짧은 fade/slide(150–200ms)만. 부드럽고 과하지 않게.
- **AI 슬롭 금지**(RULES 후보): glassmorphism(backdrop blur), gradient-text, 보라/인디고 브랜드색,
  네온 글로우, 배경 gradient orb, "Powered by AI" 배지, 균일 rounded-2xl 남발.

- **manifest**: `name`="환갑잔치 안내", `short_name`="환갑잔치", `display`="standalone",
  `start_url`="/", `background_color`="#FFF9F3", `theme_color`="#E07A5F", icons 192·512.
- **iOS 홈화면**: `apple-touch-icon`, `apple-mobile-web-app-capable`, status bar 메타 포함.
  iOS는 Safari 공유 시트→"홈 화면에 추가" 경로 안내 문구를 첫 진입에 한 번(선택).
- **service worker**: 앱 셸 캐시 + 일정 데이터는 **network-first(캐시 폴백)**. 온라인이면 최신
  일정이 이기고, 오프라인/약전계에서만 직전 캐시를 보여준다(캐시가 신선도를 가리지 않게).
- **접근성**: 시맨틱 마크업, 포커스 가시화, 대비 AA, **터치 타깃 ≥48px(주요 버튼 56px)**, 본문
  ≥18px, rem 기반으로 기기 글씨 확대 대응.

## 기술 설계 (Architecture)

### 스택
- Next.js 15 (App Router), TypeScript strict mode
- Tailwind CSS
- 저장소: **Upstash Redis** — 일정 JSON 단일 문서, key `itinerary`. HTTP API라 서버리스 친화.
  ("Vercel KV" 브랜딩은 Upstash 기반 마켓플레이스로 이전되어 결합을 피하고 Upstash로 직접 핀.)
- 배포: Vercel 무료. PWA: `manifest.json` + service worker.

### 데이터 모델 (단일 JSON 문서)
```ts
type Itinerary = {
  title: string;        // "조인수·김인숙 여사님 환갑잔치"
  subtitle?: string;
  timezone: "Asia/Seoul";
  version: number;      // 낙관적 동시성 — 저장 시 +1, PUT가 기대 version 검증
  updatedAt: string;    // ISO datetime
  days: Day[];
};
type Day = {
  id: string;
  date: string;         // ISO date, 예: "2026-09-19"
  label: string;        // "1일차"
  items: ScheduleItem[];
};
type ScheduleItem = {
  id: string;
  startTime: string;    // "HH:mm" (해당 day의 date 기준)
  endTime?: string;     // 선택
  title: string;
  location?: string;    // 텍스트만 (지도/길찾기는 비목표)
  note?: string;
};
```

### 저장소 추상화 (락인 회피 + 오프라인 테스트)
`storage` 인터페이스로 KV를 감싼다:
```ts
interface ItineraryStore {
  get(): Promise<Itinerary | null>;
  put(next: Itinerary, expectedVersion: number): Promise<Itinerary>; // version 불일치 시 throw
}
```
- `UpstashStore` — 프로덕션 구현(Redis key 1개).
- `MemoryStore`/`FileStore` — 로컬 개발·Vitest용. **네트워크 없이 테스트 통과**(검증 우선 원칙).
- 어떤 구현을 쓸지는 env로 선택. KV 미설정 로컬에서도 앱이 동작.

### 상태 계산 (핵심 로직)
순수 함수 `getItemStatus(item, day, now): "past" | "current" | "upcoming"`.
- day.date + item.startTime/endTime을 **Asia/Seoul 기준**으로 합성해 now와 비교.
- **시간은 tz-aware로 계산**(`Intl.DateTimeFormat` timeZone 또는 `date-fns-tz`). `new Date()`의
  기기 로컬 tz에 의존하지 마라. 이유: 해외 가족·기기 시간 오류 시 강조가 틀어진다(상태 정확성 핵심).
- endTime 없으면 같은 day 안의 **다음 item.startTime**을 종료 경계로 사용. 그 day의
  마지막 item이면 기본 60분으로 간주.
- 화면이 아니라 **순수 함수**로 분리 → Vitest로 테스트 가능(검증 우선 원칙).

### 라우트 & 읽기 경로(신선도)
- `/` — 공개 타임라인. **서버 컴포넌트가 `storage.get()`으로 초기 데이터를 읽어** 렌더(크리덴셜
  서버측 유지, 클라이언트 fetch 왕복 제거). 클라이언트 컴포넌트는 **30–60초마다 "지금"만 재계산**.
- `/admin` — 비밀번호 입력 → 서버 검증 → httpOnly 쿠키 세션 → 일정 편집 폼(모바일 친화).
- `app/api/itinerary` — route handler. `GET`(공개 읽기), `PUT`(보호된 전체 저장, `expectedVersion`
  포함). 쓰기 성공 시 **`revalidatePath('/')` 온디맨드 무효화** → 편집 직후 공개 화면 즉시 신선.
- `app/api/admin/login` — 비밀번호 검증 후 쿠키 발급.

> 신선도 ↔ 캐싱 원칙: 평소엔 캐시로 싸게, **admin 저장 때만** 온디맨드 revalidate. 매 로드 KV
> 직접 조회로 낭비하지 않고, 정적 캐시로 편집이 늦게 보이지도 않게 한다.

> CLAUDE.md CRITICAL 준수: 모든 데이터(KV) 접근은 서버(서버 컴포넌트·`app/api/` route handler)
> 에서만. 클라이언트 컴포넌트가 KV·외부 서비스를 직접 호출하지 않는다.

### 동시 편집 (낙관적 동시성)
편집자는 보통 1명이지만, 드문 동시 편집의 덮어쓰기를 막는다. `/admin`은 로드한 `version`을 들고
있다가 `PUT`에 `expectedVersion`으로 보낸다. 서버는 현재 `version`과 다르면 **409로 거부**하고
"다른 곳에서 일정이 바뀌었어요. 새로고침 후 다시 저장" 안내. 성공 시 `version+1`·`updatedAt` 갱신.

### 인증 (회원가입 없음)
공용 비밀번호 1개(env `ADMIN_PASSWORD`). `/admin`에서 입력 → 서버가 **상수시간 비교**로 검증 →
서명된 httpOnly 쿠키 설정. 쓰기 route handler가 쿠키를 검증. 계정·세션DB 없음. KV 크리덴셜은
클라이언트에 절대 노출하지 않는다.

## Success Criteria

- 공개 `/`에서 날짜 탭으로 일정을 보고, 현재 시각 기준 "지금 진행 중" 일정이 강조된다.
  (Playwright: 시간 고정 mock으로 강조 대상 검증)
- `getItemStatus` 순수 함수가 past/current/upcoming을 정확히 판정한다. (Vitest)
- `/admin`에서 올바른 비밀번호로 들어가 일정을 추가하면 공개 `/`에 반영된다. (Playwright)
- 틀린 비밀번호로는 쓰기가 거부된다. (Vitest/통합)
- `expectedVersion`이 현재와 다르면 저장이 409로 거부된다(낙관적 동시성). (Vitest)
- 저장소는 인터페이스 뒤에 있고, `MemoryStore`로 네트워크 없이 테스트가 돈다. (Vitest)
- 진입 시 스크롤 없이 **현재 상태 카드**(지금 진행 중 / 다음 / 기간 전·후)가 먼저 보인다. (Playwright)
- 시간이 흘러도 강조가 따라간다: 클라이언트가 30–60초마다 KST 기준으로 상태를 재계산한다.
  (Vitest: 시각을 바꿔가며 상태 카드 대상이 바뀌는지)
- 빈 상태·에러 상태가 정의된 카피로 표시된다. (Playwright)
- 디자인 토큰(크림/브라운/살구)·타입 스케일 준수, 본문 ≥18px, 시간/제목은 더 크게, 대비 AA,
  터치 타깃 ≥48px(주요 버튼 56px). AI 슬롭 안티패턴 미사용. (UI step에서 `/design-review`로 검증)
- `manifest.json`이 있어 모바일에서 홈화면 추가가 가능하다.
- 핵심 화면 E2E가 **아이폰(WebKit/Mobile Safari)·안드로이드(Chromium/Mobile Chrome) 두 기기
  에뮬레이션**에서 모두 통과한다. (Playwright `projects`=iphone·android. 실물 기기는 헤드리스
  불가 → 기기 에뮬레이션으로 대체.)
