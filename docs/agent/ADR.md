# Architecture Decision Records

> **Refs**: [ARCHITECTURE](../dev/ARCHITECTURE.md) · [ISSUES](./ISSUES.md) · [RULES](./RULES.md)

## 철학
MVP 단순함 최우선. 가족 일회성 행사용이므로 **외부 의존성·운영 부담을 최소화**하고, 작동하는
최소 구현을 택한다. 과설계(관계형 DB·계정 시스템) 금지. 근거 설계는
[design spec](../superpowers/specs/2026-06-17-hwangab-family-app-design.md).

---

### ADR-001: 저장은 Next.js + 가벼운 KV(JSON 단일 문서)
**결정**: Next.js 15 풀스택 + KV에 일정 JSON 한 덩어리. 관계형 DB(Prisma/Postgres) 미사용.
**이유**: 데이터가 작은 단일 문서(읽기 위주, 쓰기 드묾). "무재배포 편집 + 무료 + PWA"를
만족하면서 하네스 Next 템플릿을 그대로 탄다. 관계형 DB는 과설계.
**트레이드오프**: 구조화 쿼리·다중 행사 확장은 포기(필요 시 교체표대로 Postgres).

### ADR-002: 저장소를 Upstash Redis로 핀
**결정**: "Vercel KV" 브랜딩 대신 Upstash Redis 직접 사용.
**이유**: Vercel KV가 Upstash 기반 마켓플레이스로 이전됨 — 결합을 피하고 HTTP API로 서버리스
친화. 키 1개에 JSON.
**트레이드오프**: Upstash 계정·토큰 필요(사용자 개입). `storage` 인터페이스로 추상화해 완화.

### ADR-003: 인증은 공용 비밀번호 1개(무회원)
**결정**: 계정 없이 공용 비밀번호 + 서명 httpOnly 쿠키로 `/admin` 보호. 읽기는 public.
**이유**: "회원가입 없음" 요구. 가족 일회성 행사에 계정 시스템은 과함.
**트레이드오프**: 편집자별 권한 분리 불가(편집자 1명 가정). 비공개성은 by obscurity.

### ADR-004: "지금" 강조는 클라이언트 시계, 데이터는 서버 읽기 + 온디맨드 revalidate
**결정**: 라이브 강조는 클라이언트가 30–60초마다 재계산. 데이터는 Server Component가 KV에서
읽고, admin 저장 시 `revalidatePath('/')`로 무효화.
**이유**: 시간은 클라이언트에서 흐르므로 서버 불필요. 평소 캐시로 싸게, 편집 직후엔 즉시 신선.
**트레이드오프**: 즉시 실시간 동기화는 아님(저장 기준 갱신). 가족 규모엔 충분.

### ADR-005: 낙관적 동시성(version)
**결정**: 문서에 `version`/`updatedAt`. PUT은 `expectedVersion` 포함, 불일치 시 409.
**이유**: 드문 동시 편집의 덮어쓰기 방지(저비용).
**트레이드오프**: 충돌 시 사용자가 새로고침 후 재저장(편집자 1명이라 거의 발생 안 함).

### ADR-006: 시간은 항상 Asia/Seoul(tz-aware)
**결정**: 상태 계산은 `Intl`/`date-fns-tz`로 KST 고정. 기기 로컬 tz 의존 금지.
**이유**: 해외 가족·기기 시간 오류 시 강조가 틀어지는 걸 방지(상태 정확성 핵심).
**트레이드오프**: 약간의 변환 코드. 정확성을 위해 감수.

### ADR-007: 다정한 파스텔 + 큰 글씨 디자인
**결정**: 크림(#FFF9F3)/잉크(#3D3430)/살구(#E07A5F) 팔레트, 본문 ≥18px, 버튼 ≥48px(주요 56px).
**이유**: 환갑잔치 = 어르신 시청자 비중 큼. 가독성·터치 정확성 최우선.
**트레이드오프**: 정보 밀도↓(큰 글씨). 대상에 맞는 의도적 선택.

### ADR-008: 날짜별 동선 지도 추가(초기 "지도 비목표" 결정 일부 번복)
**결정**: 사용자 요청으로 선택한 날의 동선 지도(Leaflet+OSM, 키 없음)와 음식·숙소 🔗 링크(새 탭)를
추가. `ScheduleItem`에 optional `url`·`lat`·`lng` 추가. 좌표 없는 항목은 지도 미표시. 근거 설계는
[day-route-map spec](../superpowers/specs/2026-06-18-day-route-map-design.md).
**이유**: 초기 MVP는 깔끔함 위해 지도를 비목표로 뒀으나(원 설계 spec), 가족 동선 가시화 가치가 커서
명시적 요청에 따라 도입. **턴바이턴 길찾기/내비게이션은 여전히 비목표** — 읽기 전용 동선 시각화만.
**트레이드오프**: Leaflet(~40KB gzip)·OSM 타일 네트워크 의존(오프라인 PWA 타일 미표시, 타임라인은 정상).
좌표는 데모 프리셋이며 가족 편집기(텍스트만)에 좌표 입력 UI는 후속 과제.
