# 이슈 · 반복 문제

> **Refs**: [RULES](./RULES.md) · [ADR](./ADR.md)

**개발/실행 중에 발생한 이슈**(에러, 막힌 지점, 버그, 반복되는 실수)를 기록한다. step 실행 중
`error`/`blocked`가 나거나 같은 실수를 반복하면 여기에 남긴다. (step의 `error_message`·
`blocked_reason`이 1차 소스다.)

> **승격 규칙**: 같은 문제·실수가 **3회 이상 반복되면** 일회성 이슈가 아니라 구조적 문제다.
> 아래 "반복 이슈 추적"에서 발생 횟수를 세고, 3회에 도달하면 [RULES](./RULES.md)의 불변 규칙으로
> **승격**한 뒤 이 표에서는 닫는다.

## 이슈 로그
개발 중 발생한 이슈를 발생 순서대로 기록한다.

| # | 발생 위치(phase/step) | 이슈 | 원인 | 해결 / 상태 |
|---|---|---|---|---|
| I1 | 0-mvp / E2E 전체 검증 | 전체 `npx playwright test` 시 timeline R8·admin 반영 테스트 간헐 실패(각 spec 단독은 통과) | 단일 인메모리 저장소 공유 + `fullyParallel` 병렬 → 동시 시드·`revalidatePath('/')` 레이스로 기대 상태가 덮임 | `playwright.config` 직렬화(`fullyParallel:false`, `workers:1`). resolved |

## 알려진 한계 · 기술 부채 (설계 단계 예상)
- 비공개성은 by obscurity(링크를 아는 사람만) — 민감 정보 미게재로 완화.
- Upstash·Vercel 계정/배포는 사용자 개입 필요(배포 step에서 blocked 처리 가능).
- 라이브 강조는 저장 기준 갱신(실시간 푸시 아님) — 가족 규모엔 충분.
